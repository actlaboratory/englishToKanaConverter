# 辞書編集方針: 部品語の読みと複合語の読みの一貫性

## 1. 背景・目的

[issue #5](https://github.com/actlaboratory/englishToKanaConverter/issues/5)は、「[issue #4](https://github.com/actlaboratory/englishToKanaConverter/issues/4)で議論されたような話題が今後も出てくる可能性が高いため、辞書の編集方針を明確にして文書化する」ことを求めている。issue #4は`where`・`when`等の`wh`の発音の扱いについての議論で、「英語の実際の発音に忠実であるべきか」と「聞き分けやすさ（他の語と区別できること）を優先すべきか」というトレードオフが論点になった。

本ドキュメントは、その論点が実際に辞書のどこに・どのくらい表れているかを`dictionaries/phrases.json`（約49,000件、[issue15-dictionary-json-format.md](./issue15-dictionary-json-format.md)参照）に対する調査によって特定し、方針を明文化したものである。対象読者は、辞書に新しい語を追加する開発者、および既存の読みの妥当性を判断する必要がある開発者を想定する。

機械的な整合性チェックだけでは洗い出せない表記ゆれもあるため、個々のエントリーを丁寧にレビューする作業を継続的に行い、見つかった不統一と、それに対する方針をこのドキュメントに随時追記していく。

変換アルゴリズム自体（どの辞書をどう参照するか）については[conversion-logic.md](./conversion-logic.md)を、辞書ファイルの形式的なルール（使用可能文字、最適化コマンド等）についてはREADME.mdの「辞書のメンテナンス」節を参照。本ドキュメントは、**個々の語の読みをどう決めるか（言語的な方針）**に焦点を当てる。


### 1.1 辞書全体を貫く基本原則

本辞書の大部分が由来する`bep-eng.dic`は、日本語のTTSに英語を読ませることを目的として作られたものである。DOS時代に主流だったVSUという音声合成装置で読ませたときに**英語らしく聞こえる**よう、意図的なチューニングが施されている。`IT`を日本語として自然な`イット`ではなく`イットゥ`とするのがその典型で、**表記の自然さよりも、読み上げたときの聞こえが英語に近いこと**を優先している。

この設計思想は現在の辞書にも一貫して受け継がれており、実測すると次の通りである。

| 細工 | 英語寄り | 日本語寄り | 適用率 |
| --- | --- | --- | --- |
| 語末の/t/ | `トゥ` 4,986件 | `ト` 63件 | 98.7% |
| 語末の/d/ | `ドゥ` 5,129件 | `ド` 41件 | 99.2% |
| /ti/ | `ティ` 6,171件 | `チ` 1,955件 | 76% |
| /si/ | `スィ` 94件 | `シ` 7,420件 | **1.3%** |

一方、元のBEP辞書には`LOCALE`を`ロウカール`と読ませるなど、英語らしさを追求するあまり日本語として不自然になった例も多数あった（現在は`ロケール`に修正済み）。上表で/si/だけ適用率が1.3%と際立って低いのも同じ理由で、`スィ`という表記は日本語の音韻から離れすぎるため、事実上採用されていない。つまり「どこまで英語に寄せるか」の線引きは既に存在する。

これを踏まえ、本辞書の方針を次の3層とする。**番号の順に優先度が高い**。

1. **英語の語は、英語らしく聞こえる表記を優先する。**
   語末の/t//d/を`トゥ`・`ドゥ`とするのが代表例。日本語として多少ぎこちなくても、英語の発音に近い聞こえを選ぶ。

2. **ただし、日本語として不自然になる手前で止める。** 次の場合は日本語側の形を使う。
   なお「日本語として定着した外来語だから」という理由での例外は認めない。`MICROSOFT`→`マイクロソフトゥ`、`INTERNET`→`インターネットゥ`、`HOLLYWOOD`→`ハリウッドゥ`が示す通り、定着の度合いは判断材料にしない。
   * 英語以外に由来する語（イタリア語の音楽用語`ALLEGRETTO`→`アレグレット`、スペイン語`AVOCADO`→`アボカド`など）
   * 英語以外に由来する人名・地名（`SUHARTO`→`スハルト`、`BOLOGNA`→`ボローニャ`）。英語圏の人名・地名は原則1に従う（`RICHARD`→`リチャードゥ`、`ENGLAND`→`イングランドゥ`）
   * 日本語の音韻から離れすぎる細工（/si/を`スィ`とする類）

3. **聞き分けやすさが損なわれる場合は、英語らしさより優先する。**
   [issue #4](https://github.com/actlaboratory/englishToKanaConverter/issues/4)で`WHY`を`ワイ`にせず`ホワイ`のままとしたのは、英語の実際の発音では`wh`が消えていても、`Y`との区別がつかなくなるためである。4.1節の否定接頭辞（`UNABLE`→`アンエイブル`）も同じ理由による。

なお原則1は**聞こえ**についての規定であり、表記の見た目ではない。6章で`V`を`ヴ`ではなくバ行に統一したのは、日本語TTSの多くが`ヴ`を実質`ブ`と発音するため、`ヴ`を使っても聞こえが英語に近づかず、原則2に言う「日本語の音韻から離れた細工」にあたるからである。

以降の各章は、この原則のいずれに基づく判断かを次のように位置づけている。

| 章 | 対象 | 主に依拠する原則 |
| --- | --- | --- |
| 4章 | 否定接頭辞＋母音 | 原則3（聞き分けやすさ） |
| 5章 | `suffix.json`のフォールバック | 原則1（許容範囲として据え置き） |
| 6章 | `V`の読み | 原則2（聞こえが変わらない細工は採らない） |
| 7章 | `TH`の読み | 原則1（語族内の統一） |
| 8章 | 語末`-Y`の長音 | 原則2（外来語表記の慣習） |
| 9章 | 日本語として成立しない読み | 原則以前の誤り |
| 10・11章 | /oʊ/の長音表記 | 原則1（`オウ`に統一。定着度による例外は認めない） |

## 2. 調査方法

`phrases.json`の各エントリー（見出し語Kと読みR(K)）について、Kが「既に辞書に登録されている別の語」の組み合わせ（接頭辞＋基語、基語＋接尾辞、基語＋基語）として分解できる場合に、その組み合わせの読みを単純連結したものとR(K)を比較した。

* 接尾辞: `suffix.json`の8エントリー（`S`、`ES`、`D`、`ED`、`ING`、`LY`等）を使い、`K = 基語 + 接尾辞`となる基語が`phrases.json`に存在するケースを総当たりで比較。
* 接頭辞: `prefix.json`の2エントリー（`NO`、`UN`）に加え、辞書内で高頻度に現れる`IN`・`RE`・`DIS`についても同様に、`K = 接頭辞 + 基語`となる基語が`phrases.json`に存在するケースを比較。
* 複合語: 任意の分割点で`K = 語1 + 語2`となり、語1・語2の両方が独立して`phrases.json`に存在するケース（約2,400件）も比較したが、大半は`FORMAT`+`TING`のような偶然の文字列一致であり、有益な知見は得られなかった。

## 3. わかったこと

### 3.1 屈折語尾（-s/-ed/-ing/-ly）は概ね一貫しているが、`suffix.json`のフォールバックだけが乖離している

`基語+接尾辞`の単純連結とR(K)が一致しないケースは数千件見つかったが、内容を見るとその大半は英語として正しい音便変化だった。例えば`ABATED`は`アベイトゥ`+`ドゥ`＝`アベイトゥドゥ`ではなく、正しい有声化を反映した`アベイティドゥ`になっている。`ADDRESSES`も同様に、単純連結の`アドゥレスイズ`ではなく`アドゥレシズ`という、正しい有声化・音節構造を反映した読みになっている。

つまり、**既に登録されている約49,000件は、（表記上の単純連結ではなく）実際の英語の発音パターンに概ね忠実に統一されている**。

一方、この規則性を担保しているのは個々のエントリーそのものであり、`_partsToKana`が未登録語の救済に使う`suffix.json`（`D`→`ドゥ`、`S`→`ズ`等）は単純な文字列連結しか行わない。つまり、**似た語が数百〜数千件すでに登録されているにもかかわらず、たまたま未登録の新語だけは`suffix.json`由来の不自然な読みになる**、という構造的な不統一が存在する。

この点については、`suffix.json`に音便規則を持たせて根本的に解消することも考えられるが、対象になり得る語数が非常に多く（`-s`だけで2,900件超の「不一致」候補）、語末の音（有声/無声、破裂音か否か等）に応じた分岐が必要になるなど改修コストが大きい。一方で影響範囲は「基語は個別登録されているが、屈折形は未登録の語」という限定的なケースにとどまり、多くの場合は最終手段の`_alphaToSpell`（1文字ずつのスペルアウト）よりはましな近似が得られている。そのため、この乖離は既知の制約として許容し、`suffix.json`の改修は行わない（5章参照）。

### 3.2 否定接頭辞＋母音始まりの語で、同一の音韻環境なのに読みが3パターンに割れていた

これが本調査で見つかった最も明確な不統一である。`UN-`＋母音始まりの語（`UN`が実際に「否定」を意味する生産的な複合語に限る）を洗い出すと、同じ「UN+母音」という環境にもかかわらず、次の3パターンが混在していた（修正前）。

| パターン | 例（修正前） |
| --- | --- |
| A: ンを脱落させ直接リンク | `UNABLE`→`アネイブル`、`UNARM`→`アナーム`、`UNASHAMED`→`アナシェイムドゥ` |
| B: ンを保持しつつ余分な子音（ナ行等）を挿入してリンク | `UNAWARE`→`アンナウェアー`、`UNAMUSED`→`アンナミューズドゥ`、`UNAVAILABLE`→`アンナベイラブル` |
| C: ンを保持し、そのまま母音に接続 | `UNAVOIDABLE`→`アンアボイダブル`、`UNEXPECTED`→`アンエクスペクティドゥ` |

`IN-`でも同様の混在があり（例: `INEFFECTIVE`だけが`インニフェクティブ`とB型で、`INEFFICIENT`は`イネフィシェントゥ`とA型）、さらに`INEPTITUDE`→`ニネプティチュードゥ`のような単純な脱字と見られる例もあった。

なお、`prefix.json`のもう一方のエントリーである`NO-`も同じ方法で調べたが、こちらで見つかったのは母音接続時の脱落／同化という3.2節の問題とは別種の表記ゆれだった。`prefix.json`上の`NO`の読みは`ノー`だが、`NOBODY`→`ノウボディー`、`NOFOLLOW`→`ノウフォロウ`、`NOTABLE`→`ノウタブル`のように、多くのエントリーが`ノー`ではなく`ノウ`という長母音表記になっている。これは接頭辞と母音始まりの基語の結合方法の問題ではなく、/oʊ/という二重母音をどう表記するか（`ー`か`ウ`か）という別の論点であるため、10章で改めて扱う。

参考として`RE-`接頭辞（約250件）も調べたが、`REACT`→`リアクトゥ`、`REASSEMBLE`→`リアセンブル`、`REORGANIZE`→`リオーガナイズ`のように、ほぼ全件が「接頭辞の読みをそのまま、余分な音を足さずに基語の読みへ接続する」形で統一されていた。ただし、これを「`UN-`/`IN-`でも同じように統一できる根拠」として扱うのは誤りである。`RE`は既に母音`イ`で終わる1モーラ（`リ`）であり、直後に母音が続いても読み方の選択肢自体が存在しない（`リ`+母音は常に`リ`+母音にしかなり得ない）。一方`UN`/`IN`の`N`は撥音（モーラ音素としての「ン」）であり、日本語の音韻として、直後に母音が続く場合に「ンのまま残す」か「ナ行などに同化する」かという**本当の意味での選択の余地**がある。3.2節で見つかった表記揺れは、この撥音特有の曖昧さに起因するものであり、`RE-`のように「母音接続に選択肢がない」環境が一貫していたことは、その曖昧さの解消策としては参考にならない。

この不統一の原因を、本リポジトリでの[Bilingual Emacspeak Projectの`bep-eng.dic`](http://www.argv.org/bep/)と[HISSの読み辞書](https://github.com/actlaboratory/HISS-dictionary)の統合に求めるのは正確ではない。HISS辞書由来でこのリポジトリに追加された語はそれほど多くなく、辞書の大部分は`bep-eng.dic`に由来する。`bep-eng.dic`自体が、GPL化される以前から長い歴史を持ち、複数のメンテナーの手を経て作られたデータである。撥音の実現方法という、そもそも複数の答えがあり得る箇所であるがゆえに、`bep-eng.dic`の成立過程で担当者ごとに異なる選択がなされたまま残った、というのが実態に近いと考えられる。より詳しい経緯を追う場合は、`bep-eng.dic`の元データを管理している[bep-argv/bep-ss](https://github.com/bep-argv/bep-ss)リポジトリも参考になる。

### 3.3 「語源的には接頭辞＋基語だが、現代英語では分割されない語」は対象外とすべき

上記の調査対象を`DIS-`＋母音にも広げたところ、`DISASTER`（`ディザスター`、基語`ASTER`＝`アースター`）や`DISEASE`（`ディジーズ`、基語`EASE`＝`イーズ`）が「不一致」として検出された。しかしこれらは語源的には`dis`+`aster`／`dis`+`ease`でも、現代英語の話者には分割不能な一つの単語として発音される（`disease`は`ディスイーズ`ではなく`ディジーズ`が正しい）。

このような語を無理に「接頭辞＋基語の直接連結」に合わせると、かえって誤った読みになる。したがって3.2節の方針は、**現代英語話者にも「否定＋既存の語」という構造が意味的・音声的に透けて見える生産的な複合語にのみ適用し、`DISEASE`・`DISASTER`や、`UNION`・`UNIQUE`・`UNIONIZE`（`uni-`＝「一つの」に由来し、否定の`un-`ではない）のような、たまたま同じ綴りで始まる別語源の語には適用しない**。

## 4. 決定した方針

### 4.1 否定接頭辞＋母音始まりの語: 「ンを保持し、余分な音を挿入せず基語の読みへ直接接続する」方式に統一する

3.2節のC型を既定の方針とする。前節の通りこれは`RE-`接頭辞の一貫性を根拠にした選択ではない。根拠は以下の通り。

* `prefix.json`の`UN`エントリーによる自動分解（後述）が実際に生成する読みと一致し、新規登録時に判断がぶれにくい。
* issue #4での`wh`の議論と同じく、否定を表す接頭辞（`アン`/`イン`）を構成する`ン`を保持したほうが、語の意味的な区切りが聞き取りやすい。ンを脱落させる（A型）と、否定の接頭辞が付いているかどうかが読み上げだけでは分かりにくくなる。
* B型（ンを保持しつつ子音を追加する）は、単純な連結ルールとして説明・再現がしにくい。

これを踏まえた具体的なルールは次の通り。

* `UN-`・`IN-`など子音で終わる否定接頭辞は、その接頭辞自体の読み（`UN`→`アン`、`IN`→`イン`）をそのまま使い、母音で始まる基語の読みへ直接連結する。基語の頭母音を消したり（3.2節のA型）、聞き取りやすさのために子音を追加で挿入したり（3.2節のB型）しない。
* 基語は、独立した単語として辞書に既に登録されている読みをそのまま使う。基語側の読みを複合語用に変更しない。
* 例: `UN`(`アン`)+`ABLE`(`エイブル`)=`UNABLE`→`アンエイブル`。`IN`(`イン`)+`ORGANIC`(`オーガニック`)=`INORGANIC`→`インオーガニック`。
* 適用対象は3.3節の条件（現代英語でも否定接頭辞＋独立した基語という構造が透けて見える生産的な複合語）を満たす語に限る。`DISEASE`型の融合語や、`UNION`型の別語源語は対象外。

なお、[prefix.jsonの`UN`エントリー](../englishToKanaConverter/dictionaries/prefix.json)を使った自動分解（`_partsToKana`）は、この方針に従うと実際に生成される読みと一致する。つまり`UN-`語であれば、この方針に従う限り`phrases.json`に個別登録しなくても自動分解だけで正しい読みが得られる。一方`IN`は`prefix.json`に登録されていない（登録されているのは`NO`・`UN`のみ）ため自動分解の対象にならず、`IN-`語は今後もこの方針に沿った読みを`phrases.json`に個別登録する必要がある。

この方針に基づき、3.2節で検出したA型・B型の実在する不統一エントリー33件（`UN-`16件、`IN-`17件。`UNARY`・`UNION`・`UNIONIZE`・`UNIONIZED`・`UNITS`・`INITS`は3.3節の理由により対象外とし据え置いた）を、本ドキュメントの追加と同じ変更でC型に修正済みである。

### 4.2 今後の新規登録時のチェック方法

新しく否定接頭辞＋母音始まりの語を登録する際は、次の手順で確認する。

1. その語が3.3節の条件（意味的に分割可能な生産的複合語）を満たすか確認する。満たさなければ、実際の発音に基づき自由に読みを決めてよい（4.1節の方式に従う必要はない）。
2. 満たす場合、接頭辞の読み（`UN`→`アン`、`IN`→`イン`等）と、基語の辞書登録済みの読みをそのまま連結した読みを採用する。
3. 連結した結果が明らかに不自然（実際にそう発音されない）と感じる場合は、個別に判断してよいが、その判断根拠をコミットメッセージ等に残し、同じ接頭辞の他のエントリーとの整合性を`tools/optimizeDic.py`実行前に確認する。

## 5. 許容することにした既知の不統一

3.1節で触れた`suffix.json`（`-s`/`-ed`/`-ing`/`-ly`等の未登録語向けフォールバック）の読みが、`phrases.json`内で実際に使われている音便パターンと乖離している問題は、**許容し、当面`suffix.json`の改修は行わない**方針とした。

* 影響範囲は「基語は個別登録されているが、当該の屈折形自体は未登録」という語に限られ、既に個別登録されている約49,000件の読みには影響しない。
* 語末の音（有声/無声、破裂音か否か等）に応じた分岐が必要になり、改修コストが対象語数（`-s`だけで2,900件超の「不一致」候補）に見合わない。
* この乖離が生じても、結果は最終手段の`_alphaToSpell`（1文字ずつのアルファベット読み上げ）よりは自然な近似になっており、実用上致命的ではない。

今後、この判断を覆すだけの実害（誤読による問い合わせの増加等）が確認された場合は、改めてissueを起票して再検討する。

## 6. `V`の文字の読み方: 基本的にバ行に統一する

否定接頭辞のケースとは別に、個々のエントリーを丁寧にレビューしていく中で見つかった不統一の1つ目として、`V`の文字（`ヴ`か、バ行`バ・ビ・ブ・ベ・ボ`か）の表記ゆれを扱う。今後も同様に、レビューで見つかった不統一をこの形式で追記していく。

### 6.1 調査で見つかったこと

見出し語に`V`を含むエントリーは`phrases.json`に約4,000件あるが、読みに`ヴ`（`ヴァ・ヴィ・ヴ・ヴェ・ヴォ`）が使われているのは1,147件にとどまり、大半はバ行で読まれている。単に少数派というだけでなく、**同一語族の中で`ヴ`とバ行が入り混じっている**ケースが多数見つかった。

| 語族 | 揺れの実例 |
| --- | --- |
| `GOVERN-` | `GOVERN`→`ガヴァン`／`GOVERNED`→`ガヴァンドゥ`／`GOVERNMENT`→`ガヴァメントゥ`に対し、`GOVERNANCE`→`ガバナンス`／`GOVERNMENTAL`→`ガバメンタル`／`GOVERNMENTS`→`ガバメンツ` |
| `-VOLVE` | `DEVOLVE`→`ディボルブ`／`EVOLVE`→`イボウルブ`／`INVOLVE`→`インボルブ`／`REVOLVE`→`リボルブ`（`ヴ`なし）に対し、`CONVOLVE`→`コンヴォルヴ`／`REVOLVER`→`リヴォルヴァー`（`ヴ`が2つ） |
| `CONSERVE` | `CONSERVE`→`コンサーブ`（`ヴ`なし）に対し、同じ語の活用形`CONSERVED`→`コンサーヴドゥ`／`CONSERVING`→`コンサーヴィング`（`ヴ`あり） |
| `ADVISE` | `ADVISE`→`アドゥバイズ`／`ADVISER`→`アドゥバイザー`に対し、`ADVISEE`→`アドゥヴァイジー`／`ADVISES`→`アドゥヴァイジズ` |
| `TRAVELER`/`TRAVELLER` | 米式`TRAVELER`→`トゥラベラー`に対し、英式`TRAVELLER`→`トゥラヴェラー`（綴りの違いだけで表記が変わっている） |
| `VIRUS` | `VIRUS`→`バイルス`（独語風）、`ANTIVIRUS`→`アンティウイルス`（和製慣用語）、`CYTOMEGALOVIRUS`→`サイトゥメガロヴァイラス`（英語風）と3通りが混在 |

一方、`DEVELOP`系・`COVER`系・`VOKE`系（`CONVOKE`/`EVOKE`/`INVOKE`/`PROVOKE`/`REVOKE`）は語族内で完全に統一されており、バ行での統一自体は現実的に可能であることが分かる。

### 6.2 決定した方針

`V`の文字は、**基本的にバ行（`バ・ビ・ブ・ベ・ボ`）で読む**ことを既定の方針とする。`ヴ`は原則として使わない。

* 辞書の多数派が既にこの方式で統一されており、バ行を既定にすることで修正が必要な範囲（少数派の`ヴ`表記側）を最小化できる。
* `VIRUS`（`ウイルス`）のように、日本語の慣用読みとして定着している別形がある語は、この方針の対象外とし、慣用読みを優先してよい。
* `B`と`V`の聞き分けが必要になる特殊な文脈が将来的に見つかった場合は、個別に例外として判断し、その理由をコミットメッセージに残す。

### 6.3 修正の実施

`ヴ`を含むエントリーは`phrases.json`に1,147件、`words.json`に1件（`VIOLETS`）あり、他の辞書・定数ファイルには存在しなかった。これらを次の対応でバ行に変換した。

`ヴ`は単独ではなく、直後の小書き母音と組んで1モーラを構成するため、**二重仮名を先に処理し、残った単独の`ヴ`を最後に`ブ`とする**順序が必要である。

| 変換元 | 変換先 | 件数 | 例 |
| --- | --- | --- | --- |
| `ヴァ` | `バ` | 590 | `VIOLIN`→`ヴァイオリン`⇒`バイオリン` |
| `ヴィ` | `ビ` | 334 | `VENUS`→`ヴィーナス`⇒`ビーナス` |
| `ヴェ` | `ベ` | 60 | `VELOCITY`→`ヴェロシティー`⇒`ベロシティー` |
| `ヴォ` | `ボ` | 25 | `ADVOCATE`→`アドゥヴォケイトゥ`⇒`アドゥボケイトゥ` |
| `ヴュ` | `ビュ` | 4 | `INTERVIEW`→`インタヴュー`⇒`インタビュー` |
| 単独の`ヴ` | `ブ` | 158 | `ABORTIVE`→`アボーティヴ`⇒`アボーティブ`、`DOSV`→`ドスヴイ`⇒`ドスブイ` |

6.2節では`VIRUS`のような慣用読みを例外として認めたが、**実際に変換した1,147件の中に例外を要する語はなかった**。`ヴィーナス`→`ビーナス`、`ヴァイキング`→`バイキング`、`ヴァニラ`→`バニラ`、`インタヴュー`→`インタビュー`のように、変換結果はいずれも日本語として標準的な表記に近づく方向に働いたためである（`VIRUS`自体は元から`バイルス`で`ヴ`を含まず、対象外だった）。

なお、`ヴ`を含む読みのうち`GRANITIC`→`ヴラニティク`だけは、見出し語に`V`が含まれないにもかかわらず語頭が`ヴ`という唯一の例だった。これは`ヴ`が`グ`の誤植であり、機械変換すると`ブラニティク`という誤った読みになるため対象から除外し、`GRANITE`→`グラニットゥ`・`GRANT`→`グラントゥ`を根拠に`グラニティク`へ個別に修正した（語尾の`ティク`は`BRONCHITIC`→`ブロンキティク`等に前例があるため変更していない）。

この修正により、6.1節で挙げた語族の不統一はすべて解消した。`GOVERN`系は`ガバン`・`ガバメントゥ`・`ガバナンス`・`ガバメンタル`がすべて`ガバ`で揃い、`CONSERVE`系は`コンサーブ`・`コンサーブドゥ`・`コンサービング`と活用形が揃い、`TRAVELER`と`TRAVELLER`は綴りの違いによる差が消えて**どちらも`トゥラベラー`**になった。

## 7. `TH`の読み方: 語族内で表記を統一し、有声/無声の誤りを修正する

3つ目にレビューしたのが、`TH`（無声`θ`・有声`ð`の両方）の読みである。`TH`を含む見出し語は約1,368件と`V`（約4,000件）よりかなり少なく、調査の結果、大半の語族は既に一貫していた。見つかった不統一は主に2種類で、性質が異なるため別々に扱う。

### 7.1 表記ゆれ（`スィ`/`ズィ` vs `シ`/`ジ` vs `スイ`）

`THINK`・`THICK`・`THEOREM`のような語族では、無声`th`+`i`の音を拡張仮名の`スィ`（`ス`+小書きの`ィ`による1モーラ表記、例: `THINK`→`スィンク`）で読むのが辞書内の多数派になっている。しかし同じ語族の中で一部だけ、通常の`シ`や、`ス`+通常サイズの`イ`（2モーラ表記の`スイ`）に戻ってしまっている例が見つかった。なお`THEATER`→`シアター`のように、`シ`表記の語族全体が最初から一貫している場合は対象外（既に定着した慣用読みとみなす）。

| 語族 | 揺れ |
| --- | --- |
| `THINK`系 | `THINK`→`スィンク`、`RETHINK`→`リスィンク`、`METHINKS`→`ミスィンクス`に対し、`BETHINK`→`ビシンク`（`シ`に戻っている） |
| `THICK`系 | `THICK`→`スィック`、`THICKEN`→`スィックン`ほか全て`スィ`なのに、`THICKENER`→`シックナー`だけ`シ` |
| `THING` | `THING`→`スィング`（`スィ`の1モーラ表記）に対し、`ANYTHING`→`エニスイング`（`ス`+`イ`の2モーラ表記） |

これは`V`のときと同種の、純粋な表記の好みの問題である。**その語族の多数派に合わせる**という方針のもと、`BETHINK`→`ビスィンク`、`THICKENER`→`スィックナー`、`ANYTHING`→`エニスィング`の3件を修正済みである。

### 7.2 有声/無声の判断そのものの誤り

`TH`は語によって無声`θ`と有声`ð`のどちらでも読まれ得るし、`WORTHY`（`ワージー`、`worth`から有声化）のように正しく有声化している語もある。そのため機械的に「無声に統一する」とは決められないが、調査の中で、**同一の接尾辞・同一の環境なのに片方だけ有声/無声が入れ替わっている**、単純な誤りと見られる例が見つかった。

| 語族 | 疑わしい点 |
| --- | --- |
| `LENGTH`/`STRENGTH` | `STRENGTH`→`ストゥレングス`→`STRENGTHEN`→`ストゥレングスン`（無声`ス`のまま）に対し、`LENGTH`→`レングス`→`LENGTHEN`→`レングザン`（同じ`-THEN`接尾辞なのに有声`ザ`に変わっていた） |
| `TOOTH` | `TOOTH`→`トゥース`（無声）に対し、`TOOTHY`→`トゥージー`／`TOOTHING`→`トゥージング`（有声`ジ`になっていた） |

`STRENGTHEN`という直接比較可能な対照例があることから、単なる誤記と判断し、`LENGTHEN`→`レングスン`、`LENGTHENED`→`レングスンドゥ`、`LENGTHENING`→`レングスニング`、`TOOTHY`→`トゥーシー`、`TOOTHING`→`トゥーシング`に修正済みである。ただし、この種の判断（語ごとに実際の発音がどちらであるかの正誤判定）は`V`の表記ゆれとは異なり言語知識に基づく個別判断であり、明文化できる一般規則ではない。今後同様の疑わしい例を見つけた場合も、直接対照できる同型の語（`STRENGTH`と`LENGTH`のような対）がある場合に限り修正し、確証が持てない場合は無理に修正しない。

## 8. 語末`-Y`の長音表記: 長音記号`ー`に統一する

4つ目にレビューしたのが、語末が`-Y`で終わる語（`-LY`、`-ITY`、`-OLOGY`などを含む）の、末尾の長音の書き方である。これは本ドキュメントで扱った中で最大規模の不統一だった。

### 8.1 調査で見つかったこと

語末が`-Y`の見出し語は`phrases.json`に4,312件あるが、まったく同じ音である末尾の長音が3通りに書き分けられていた（修正前）。

| 表記 | 件数 | 例 |
| --- | --- | --- |
| `ー`（長音記号） | 2,776件（64%） | `ABILITY`→`アビリティー`、`ACADEMICALLY`→`アカデミカリー` |
| `イ`（通常サイズ） | 1,467件（34%） | `ACCLIVITY`→`アクリビティイ`、`ACRONYMICALLY`→`アクロニミカリイ` |
| `ィ`（小書き） | 44件（1%） | `ABDOMINALLY`→`アブドミナリィ` |

決定的なのは、**同一の接尾辞の中ですら割れていた**点である。音はまったく同じであり、意図的な使い分けとは考えられない。

| 接尾辞 | `ー` | `イ` |
| --- | --- | --- |
| `-ICALLY` | 156件 | 93件 |
| `-ABILITY` | 66件 | 26件 |
| `-OLOGY` | 68件 | 23件 |
| `-ATIONALLY` | 9件 | 17件（ここだけ`イ`が多数派） |

`-ATIONALLY`だけ多数派が逆転していることからも、規則ではなく単なる揺れであることが分かる。

### 8.2 決定した方針

語末`-Y`の長音は、**長音記号`ー`で表記する**ことを既定の方針とする。

* 既に64%がこの形であり、修正対象を最小化できる。
* 内閣告示「外来語の表記」が定める長音の書き方（`ー`を用いる）に合致し、`パーティー`・`アカデミー`・`コピー`といった一般的な外来語表記とも整合する。
* `-ITY`が既に`ティー`で揃っている（`アビリティー`）ことと、同じ形になる。

### 8.3 修正時の重要な注意点: 二重母音と長音の区別

**「末尾の`イ`を`ー`に置き換える」という単純な一括処理を行ってはならない。** 語末`-Y`で読みが`イ`で終わる1,467件のうち、290件超は長音ではなく**二重母音**であり、`イ`が必須である。

| 直前の仮名 | 意味 | 例 | 扱い |
| --- | --- | --- | --- |
| イ段（`リ`・`ティ`・`シ`など） | 長音 /iː/ | `アクリビティイ` | `ー`に直す |
| エ段 | 二重母音 /ei/ | `ALLAY`→`アレイ`、`ASHLEY`→`アシュレイ` | **変更しない** |
| ア段 | 二重母音 /ai/ | `ALLY`→`アライ`、`APPLY`→`アプライ` | **変更しない** |
| オ段 | 二重母音 /oi/ | `ANNOY`→`アノイ`、`ALLOY`→`アロイ` | **変更しない** |

この判定に基づき、`イ段`の直後の`イ`・`ィ`のみを`ー`に変換する形で1,174件を修正した。あわせて、長音記号の後に余分な`イ`が付いていた`PECUNIARY`→`ピキューニエアリー`（元は`ピキューニエアリーイ`）を単発で修正し、計1,175件を変更済みである。

変換対象から除外したのは337件で、その内訳は次の通り。このうち`PECUNIARY`1件のみを上記の通り個別に修正したため、336件は修正前のまま保持されており、全件を検証済みである。

| 除外した理由 | 件数 |
| --- | --- |
| 真の二重母音（ア段・エ段・オ段＋`イ`） | 290件 |
| 小書きの`ィ`で終わる（8.4節の積み残し） | 30件 |
| その他（`ベルボーイ`・`アンツイ`など） | 17件 |

### 8.4 長音化されていない語の扱い

8.3節の修正後も、**そもそも長音になっておらず、短いまま終わっている**語が54件残った。これは`ー`と`イ`のどちらを使うかという8.1節の論点とは別の、第3の変種である。`ティ`・`ディ`のように小書きの`ィ`を含む二重仮名（`テ`＋`ィ`で1モーラのイ段音）で終わるものが多く、8.3節の「直前がイ段か」という機械的判定では拾えなかった。

一括処理はできない。`POLY`→`ポリ`（`ポリ袋`）のように**短い形が日本語として定着している語**が混ざっているためである。そこで各語について、同じ接尾辞を持つ語が辞書内で多数派としてどうなっているかを集計し、その証拠に基づいて個別に判断した。結果、**46件を修正し、7件を据え置いた**（54件のうち`IRREDUCIBLY`は9.2節で修正済み）。

**修正した46件** — 同一接尾辞の兄弟語の圧倒的多数が長音であることを根拠とする。

| 例 | 修正内容 | 根拠となった兄弟語の状況 |
| --- | --- | --- |
| `IMMUTABILITY` | `イミュータビリティ`→`イミュータビリティー` | `-BILITY`の134件中133件が長音 |
| `FECUNDITY` | `フィカンディティ`→`フィカンディティー` | `-DITY`の31件すべてが長音 |
| `SUBJECTIVITY` | `サブジェクティビティ`→`サブジェクティビティー` | `-TIVITY`の17件すべてが長音 |
| `APOLOGY` | `アポロジ`→`アポロジー` | `-OLOGY`の93件中92件が長音 |
| `FLOPPY` | `フロッピ`→`フロッピー` | `-OPPY`の5件すべてが長音 |
| `RESERVEDLY`ほか7件 | `リザービドゥリ`→`リザービドゥリー` | `-EDLY`全17件中10件が`ドゥリー`で多数派 |

このうち`ICKY`のみ、長音だけでなく促音も欠けていたため`イキ`→`イッキー`とした（`GIMMICKY`→`ギミッキー`、`COLICKY`→`コリキー`に合わせた）。

**据え置いた7件**

| 見出し語 | 読み | 据え置いた理由 |
| --- | --- | --- |
| `POLY` | `ポリ` | `ポリ袋`・`ポリエステル`として短い形が定着 |
| `EPOXY` | `エポキシ` | `エポキシ樹脂`として定着 |
| `METHYLENEDIOXY` | `メチレンエディオキシ` | 化学用語の`-オキシ`として定着 |
| `EVERY` | `エブリ` | 兄弟語（`BRAVERY`→`ブレイバリー`等）は`brave`+`ry`型であり、`EVERY`は`e`+`very`ではない。接尾辞の機械的一致が根拠にならない例 |
| `HOITY` / `TOITY` | `ホイティ` / `トイティ` | `hoity-toity`という一体の句で、`ホイティトイティ`が通例 |
| `GROZNY` | `グローズニ` | ロシア語地名で、日本語の慣用は`グロズヌイ`系。長音化とは別の問題を含む |

`EVERY`の例が示す通り、**接尾辞が一致するというだけで兄弟語を根拠にすると誤る**ことがある。語の成り立ち（どこが語幹でどこが接尾辞か）を確認した上で判断する必要がある。

## 9. 日本語として成立しない読みの修正

これまでの各節は「複数の妥当な表記のうちどれを選ぶか」という統一の問題を扱ってきた。これに対し本節は、**選択の余地なく誤っている**読み、すなわち日本語のカタカナ表記として成立していないものを扱う。これらは8章の修正を検証する過程で発見された。

### 9.1 検出方法

日本語のカタカナ表記では起こり得ない仮名の並びを、機械的に走査して検出した。具体的には、長音記号`ー`の重複、語頭の`ー`、撥音`ン`の直後の`ー`、語頭の小書き仮名、語末の促音`ッ`、`ッ`や`ン`の重複などである。

なお、この走査を設計する際、「小書き仮名が連続する」という条件も試したが、これは`ティッドゥ`（`ィ`＋`ッ`）や`キャッツ`（`ャ`＋`ッ`）のような正当な表記を1,179件も拾ってしまい、検出条件として使えなかった。**拗音・促音を表す小書き仮名の連続は正常である**点に注意が必要である。

### 9.2 修正した内容

いずれも同一語族内に正しい対照例があり、修正内容に判断の余地はなかった。計15件を修正済みである。

| --- | --- | --- | --- |
| `BEANPOLE` | `ビンーポール` | `ビーンポール` | `BEAN`→`ビーン`（`ン`と`ー`が入れ替わった誤植） |
| `BUSYBODY` | `ビジーボディーー` | `ビジーボディー` | `BUSY`→`ビジー`＋`BODY`→`ボディー` |

| `DITHERING` | `ディザーーリング` | `ディザリング` | `GATHERING`→`ギャザリング`、`BOTHERING`→`ボザリング`（同じ`-THER`型） |

## 10. /oʊ/の長音表記: 英語の語はオウに統一する

3.2節で先送りした`ノー`/`ノウ`の問題を扱う。調査の結果、これは`NO-`接頭辞に限った話ではなく、二重母音/oʊ/（`GOAT`の母音）を`オウ`と`オー`のどちらで書くかという、辞書全体に及ぶ論点だった。

### 10.1 調査で見つかったこと

**`ノー`/`ノウ`の分裂は、その大半が音韻的に正しい区別だった。**

| 読み | 対応する英語の母音 | 例 |
| --- | --- | --- |
| `ノー` | /ɔː(r)/ | `NORTH`→`ノース`、`NORMAL`→`ノーマル`、`NORWAY`→`ノーウェイ`、`NOUGHT`→`ノートゥ` |
| `ノウ` | /oʊ/ | `NOBLE`→`ノウブル`、`NOSE`→`ノウズ`、`NOVEMBER`→`ノウベンバー` |

つまり`NO-`で始まる語を一律に統一するのは誤りであり、`NOR-`系の語で`ノー`が使われているのは正しい。

一方、/oʊ/全体で見ると`オウ`形と`オー`形は辞書全体で約2,290対2,672とほぼ拮抗していた（修正前）。

| 修正前に`オー`だった語 | 修正前から`オウ`だった語 |
| --- | --- |
| `TOTAL`→`トータル`、`LOCAL`→`ローカル` | `BOAT`→`ボウトゥ`、`CODE`→`コウドゥ` |
| `MOTOR`→`モーター`、`GOAL`→`ゴール` | `MODE`→`モウドゥ`、`ZONE`→`ゾウン` |
| `BONUS`→`ボーナス`、`HELLO`→`ハロー` | `STONE`→`ストウン`、`HOME`→`ホウム` |

左列はいずれも日本語として定着した外来語である。当初はこれを原則2の「定着した外来語」に当たるとして`オー`のまま残す方針を採ったが、**その例外条項自体を廃止することにしたため、左列も`オウ`に寄せる**（10.2節）。

### 10.2 決定した方針

**英語の語の/oʊ/は`オウ`と書く。**「日本語として定着した外来語だから`オー`」という例外は認めない（1.1節の原則2から当該条項を削除した）。従って`TOTAL`→`トウタル`、`LOCAL`→`ロウカル`、`MOTOR`→`モウター`、`BONUS`→`ボウナス`となる。

ただし原則2の第1項（英語以外に由来する語）は残る。`BOLOGNA`→`ボローニャ`、`ALLEGRETTO`→`アレグレット`、日本語のローマ字表記（`ANDO`→`アンドー`、`JUDO`→`ジュードー`）は対象外である。

**この方針は機械的な一括変換では実現できない。** 理由と進め方は11章に記す。そのため、確実に判定できる語を選別しながら段階的に適用している。

### 10.4 語末が`ト`・`ド`のままだった語の是正（43件）

1.1節の原則1に照らすと、英語の語の語末/t//d/は`トゥ`・`ドゥ`で書かれるはずだが、`ト`・`ド`のままのエントリーが残っていた。

**まず、単純な文字列検索では対象を絞れない点に注意が必要である。** 語末が`ト`のエントリーは63件あるが、その大半は`ALTO`→`アルト`、`PROTO`→`プロト`、`ALLEGRETTO`→`アレグレット`のように、**`ト`が語末子音/t/ではなく音節/to/を表しているもの**であり、そもそも対象外である。見出し語が母音で終わるものを除外すると、真の候補は`ト`21件・`ド`23件の計44件に絞られた。

残った44件を調べたところ、**その多くに辞書内の直接的な反証があった**。

| 現状 | 反証となる同族語・同型語 |
| --- | --- |
| `STAMFORD`→`スタンフォード` | `STANFORD`→`スタンフォードゥ`（ほぼ同じ名前で扱いが逆） |
| `MOHAMMED`→`モハメド` | `MOHAMED`→`モハメドゥ`（同じ名前の綴り違い） |
| `BOLLYWOOD`→`ボリウッド` | `HOLLYWOOD`→`ハリウッドゥ`、`WOOD`→`ウッドゥ` |
| `PERIOD`→`ピリオド` | `METHOD`→`メソッドゥ` |
| `GESTALT`→`ゲシュタルト` | `SALT`→`ソルトゥ`、`MALT`→`モールトゥ` |
| `BANDICOOT`→`バンディクート` | `ROOT`→`ルートゥ`、`BOOT`→`ブートゥ` |
| `RIYADH`→`リヤード` | `BAGHDAD`→`バグダッドゥ` |
| `PINTEREST`→`ピンタレスト` | `INTEREST`→`インタレストゥ` |
| `FLYNT`→`フリント` | `FLINT`→`フリントゥ` |
| `REINTRODUCED`→`リイントゥロデュウスド` | `INTRODUCED`→`イントゥロデューストゥ` |

そこで44件のうち43件を`トゥ`・`ドゥ`に是正した。`REINTRODUCED`のみ、語末だけでなく基語`INTRODUCED`の読み全体に合わせて`リイントゥロデューストゥ`とした。

据え置いたのは`AUTHZ`→`オースゼット`の1件のみである。これは語末の`ゼット`が英字`Z`の日本語での読み（`spell.json`の`Z`→`ゼット`）であり、語末子音/t/ではないためである。

**この作業で1.1節の記述の誤りが判明したので訂正した。** 当初、原則2の例外として「人名・地名で慣用的な形がある場合（`SHEPARD`→`シェパード`、`STAMFORD`→`スタンフォード`）」を挙げていたが、辞書の実態を調べると英語圏の人名・地名にも一貫して原則1が適用されていた（`RICHARD`→`リチャードゥ`、`HOWARD`→`ハワードゥ`、`BERNARD`→`バーナードゥ`、`OXFORD`→`オクスフォードゥ`、`IRELAND`→`アイルランドゥ`、`ENGLAND`→`イングランドゥ`）。つまり`シェパード`・`スタンフォード`は慣用による例外ではなく、単なる不統一だった。原則2の人名に関する例外は、`SUHARTO`→`スハルト`のような**英語以外に由来する**人名・地名に限られる。

同様に、`BOLLYWOOD`→`ボリウッド`や`PERIOD`→`ピリオド`のような一見「日本語として定着した外来語」に見える語も、辞書は`ハリウッドゥ`・`メソッドゥ`と英語寄りに扱っていた。原則2の「定着した外来語」の範囲は、`AUTO`→`オート`や`PHOTO`→`フォト`のように、**日本語の一般語彙になりきった語**に限って解釈すべきである。英語の固有名詞やブランド名は、`MICROSOFT`→`マイクロソフトゥ`、`INTERNET`→`インターネットゥ`、`NETFLIX`→`ネットゥフリックス`が示す通り、原則1の対象である。

## 11. /oʊ/を`オウ`に寄せる作業（進行中）

10.2節の方針に基づく作業の記録である。**一括変換ができない理由**と、それに対してどう進めているかを記す。

### 11.1 機械的な一括変換ができない3つの理由

1. **`オー`という表記から/oʊ/と/ɔː/を区別できない。** `NORTH`→`ノース`（/ɔːr/、据置）と`TOTAL`→`トータル`（/oʊ/、変換）は、仮名の上では同じ「オ段＋`ー`」である。一律変換すれば`ノウス`という誤りを生む。
2. **1語の中で扱いが分かれる。** `ALSO`→`オールソー`は、前半の`オー`が`al`由来の/ɔː/で据置、後半の`ソー`が`so`由来の/oʊ/で変換となる。綴りのどの母音がどの仮名に対応するかを揃える必要がある。
3. **決め手が「語の由来」であり、綴りから導けない。** これが最大の障害である。見出し語が`O`で終わり読みが「オ段＋`ー`」で終わる語（最も判定が確実なはずの条件）を抽出すると131件あるが、その内訳は日本語のローマ字が約90件（`ANDO`＝安藤、`ENDO`＝遠藤、`HONGO`＝本郷、`JUDO`＝柔道、`SHINTO`＝神道、`FURO`＝風呂）、イタリア語等が数十件（`ALFRESCO`、`ANTIPASTO`、`BISTRO`、`MANGO`）で、**英語は10数件しかない**。`ANDO`（安藤）・`ALDO`（イタリア人名）・`AMMO`（英語）を綴りから区別する手段はない。

対象は「オ段＋`ー`」を含む3,092件・3,130箇所ある。仮に95%の精度で機械変換しても約150件の新規の誤りを作ることになり、既存の不統一より悪化する。

### 11.2 進め方

信頼できる/oʊ/の綴り（`OA`・`OW`・`OLD`・`O`＋子音＋`E`・`-OSIS`・`-OMA`など）を持ち、かつ/ɔː/を示す綴り（`AU`・`AW`・`ALK`・`ALL`・`OR`＋子音・`OUGH`など）を含まない語を候補として抽出し、**全件を目視で確認して非英語語や別母音の語を除外リストに落とす**、という手順を取っている。安全策として、「オ段＋`ー`」が2箇所以上ある語は自動変換の対象から外し、個別に扱う。

### 11.3 これまでに適用した内容（314件）

**第1バッチ 294件** — 抽出した382件から、目視で91件を除外して適用した。除外の内訳は次の通りである。

| 除外理由 | 例 |
| --- | --- |
| 英語以外に由来（原則2第1項） | `BEETHOVEN`→`ベートーベン`、`BOLOGNA`→`ボローニャ`、`GUACAMOLE`→`グアカモーレ`、`NOTO`→`ノトー` |
| /oʊ/ではない母音 | `GONE`→`ゴーン`（/ɒ/）、`OVEN`→`オーブン`（/ʌ/）、`LOSTED`→`ロースティドゥ`（/ɔː/）、`DOLL`→`ドール`（/ɒ/）、`CHOLESTEROL`（/ɒl/） |
| `オー`が英字`O`の読み | `IOSTAT`→`アイオースタットゥ`、`OLMAGAZINE`→`オーエルマガジン` |
| 読みが複雑で個別判断が必要 | `OTORHINOLARYNGOLOGY`→`オートーライノラリンゴロジー` |

**第2バッチ 20件** — 抽出用の正規表現から漏れていた常用語を手作業で補った。`LOCAL`系6件（`ローカル`→`ロウカル`ほか）、`MOTOR`系3件、`BONUS`→`ボウナス`、`HELLO`→`ハロウ`、`ECHO`→`エコウ`、`ALSO`→`オールソウ`（前半の`オール`は/ɔː/なので据置）、`AMMO`・`BUFFALO`・`HIPPO`・`LIMO`、`POST`→`ポウストゥ`（`MOST`→`モウストゥ`、`HOST`→`ホウストゥ`、`GHOST`→`ゴウストゥ`に合わせた）。

あわせて、第1バッチで`ウ`が重複した`AGLOW`→`アグロウ`と、元から誤っていた`COMEDOWN`→`カムダウン`（`ダウ`＋`ウン`）を修正した。なお`NOWAIT`→`ノウウェイトゥ`、`NOWAY`→`ノウウェイ`に残る`ウウ`は、`ノウ`（no）＋`ウェイ`（way）という形態素の境界であり正しい。

### 11.4 残っている作業

抽出条件に合致しなかった語が多数残っている。/ɔː/を示す綴りを1つでも含む語は安全側で候補から外しているため、`MOTOR`のように語末の`OR`が/ər/にすぎない語も除外されてしまう。今後、条件を緩めながら目視確認する範囲を広げていく必要がある。

また`ZERO`→`ゼロ`、`PHOTO`→`フォト`、`MEMO`→`メモ`、`LOGO`→`ロゴ`のように、語末/oʊ/がそもそも長音化されていない群がある。`SOLO`→`ソウロウ`、`HERO`→`ヒーロウ`とは既に矛盾しているが、件数と分布を調べた上で判断するため、本節の作業とは分けて扱う。

## 12. 日本語のローマ字エントリーの削除

### 12.1 経緯

`phrases.json`には、日本語をローマ字表記した見出し語が多数登録されている（`ABASHIRI`→`アバシリ`、`CHIBAKEN`→`チバケン`、`DAZAIFU`→`ダザイフ`、`DESU`→`デス`など）。これは、この辞書がVSUで発展していた時代に使われていたDOS用の日本語スクリーンリーダーVDMが、**ローマ字を読み下す仕組みを持たなかった**ためである。ローマ字をカナで読ませるには辞書に登録するしかなかった。

本モジュールは`roman.json`によるローマ字変換（`_romanToKana`）を備えているため、これらのエントリーは原則として不要である。

### 12.2 「ローマ字変換に任せられる」は自明ではない

エントリーを削除すれば`_romanToKana`が処理する、というのは**成り立たない場合がある**。変換は「辞書引き（`_partsToKana`）→ 失敗した場合のみローマ字」の順で行われるため、`phrases.json`内の英単語が部分一致すると、ローマ字変換に到達しないまま誤った読みが確定する。

| 見出し語 | 登録されていた読み | 削除した場合 | 分解のされ方 |
| --- | --- | --- | --- |
| `BANDO` | `バンドー` | `バンドゥー` | `BAN`（`バン`）＋`DO`（`ドゥー`、英語のdo） |
| `CODERA` | `コデラ` | `コッドゥエラ` | `COD`（`コッドゥ`）＋`ERA`（`エラ`） |
| `ARIDOME` | `アリドメ` | `アリドウム` | `ARI`（`アリ`）＋`DOME`（`ドウム`） |

`BANDO`について、`BAND`（`バンドゥ`）が一致して残りが`O`になる、という分解は起こらない。`O`は`phrases.json`に登録されておらず`SUFFIX`にも該当しないため、`BAND`で切った場合は再帰呼び出しが失敗し、より短い`BAN`での分解に戻る。実際に原因となっているのは`DO`である。

従って削除の可否は、**実際に削除した状態で変換して読みを比較する**という実測でしか判断できない。

### 12.3 選別の手順

1. `roman.json`によるローマ字変換の結果が登録読みと一致する（長音記号の有無を除く）エントリーを抽出 … 1,220件
2. それらを一括削除した状態で全件を変換し、読みが保たれるかを確認 … 保たれる1,159件／**破綻する61件**（`BATON`→`バットゥオン`、`HEROIN`→`ヒーロウイン`、`LITERACY`→`ライトゥレイシー`。いずれも英語）
3. 日本語のローマ字には`L`・`V`・`X`・`Q`が現れないことを利用して機械的に絞り込み … 305件を除外
4. 残る854件を**全件目視**し、日本語のローマ字だけを選別 … 325件

ここで重要なのは、**「ローマ字変換で再現できる」ことは削除の必要条件であって十分条件ではない**という点である。`BODY`→`ボディー`、`FAMILY`→`ファミリー`、`COMEDY`→`コメディー`、`BATTERY`→`バッテリー`はいずれもローマ字変換が同じ読みを返すが、それは偶然にすぎない。英語の語である以上、`roman.json`の変更で容易に壊れる状態にすべきではないため、削除の対象から外した。

### 12.4 削除した内容（318件）

選別した325件のうち、削除すると英単語の部分一致で読みが破綻する7件（`ARIDOME`・`BANDO`・`BUNDO`・`CODERA`・`DANDO`・`HAIDO`・`MANDO`。うち`-DO`で終わる5件はいずれも`DO`→`ドゥー`が原因）を除いた318件を削除した。内訳は次の通りである。

* **読みが完全に同一のまま維持される** … 230件（`ABASHIRI`→`アバシリ`、`OKINAWA`→`オキナワ`、`HITACHI`→`ヒタチ`、`DESU`→`デス`など）
* **長音記号が失われる** … 88件（`ANDO`→`アンドー`が`アンド`、`FURO`→`フロー`が`フロ`、`JUDO`→`ジュードー`が`ジュド`）

後者は、ローマ字表記`ANDO`が「あんどう」の`う`を含まない以上、ローマ字変換では復元できない情報である。登録読みの`アンドー`はそれを補うものだったが、辞書を軽くすることを優先して許容した。

削除後、エントリー数は48,977件から48,659件になった。削除した318件すべてについて変換結果を確認し、破綻がないことを検証済みである。また`BODY`・`FAMILY`・`BATON`・`HEROIN`・`LITERACY`が影響を受けていないことも確認した。

### 12.5 残っている作業

今回削除したのは、1.の抽出条件（ローマ字変換が登録読みを再現する）に合致したものに限られる。`ANDO`型のように長音記号のために一致しなかったものは拾えているが、登録読みがローマ字から大きく離れているエントリー（例: `TOKAIDO`→`トウカイドウ`、`OSHITA`→`オオシタ`のように、そもそも`phrases.json`に無いか別の読みを持つもの）は対象外である。日本語のローマ字はまだ相当数残っていると考えられるため、条件を変えた抽出を継続する必要がある。
