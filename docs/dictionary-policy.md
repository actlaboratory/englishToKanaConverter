# 辞書編集方針

## 1. このドキュメントについて

英語→カナ変換辞書に単語を登録・修正する際の判断基準をまとめたものである。[issue #5](https://github.com/actlaboratory/englishToKanaConverter/issues/5)への対応として作成した。

辞書を編集する人は、まず2章の基本原則を読み、次に該当するカテゴリの規則（3章）を参照してほしい。新しく単語を登録する際の手順は4章にまとめてある。

* 変換アルゴリズム（どの辞書がどう使われるか）は[conversion-logic.md](./conversion-logic.md)を参照。
* 辞書ファイルの形式的なルール（使用可能文字、`tools/optimizeDic.py`による最適化）はREADME.mdの「辞書のメンテナンス」節を参照。
* **各規則がどういう調査に基づいて決まったのか**、実際に何件をどう修正したのかは[dictionary-survey.md](./dictionary-survey.md)に分けて記録してある。本ドキュメントは「何をすべきか」だけを述べる。

## 2. 基本原則

### 2.1 なぜ「英語らしく聞こえる」表記なのか

本辞書の大部分が由来する`bep-eng.dic`は、日本語のTTSに英語を読ませることを目的として作られたものである。DOS時代に主流だったVSUという音声合成装置で読ませたときに**英語らしく聞こえる**よう、意図的なチューニングが施されている。`it`を日本語として自然な`イット`ではなく`イットゥ`とするのがその典型で、**表記の自然さよりも、読み上げたときの聞こえが英語に近いこと**を優先している。

一方、元のBEP辞書には`locale`を`ロウカール`と読ませるなど、英語らしさを追求するあまり日本語として不自然になった例も多数あった。したがって、英語への忠実さと日本語としての自然さのバランスを取る必要がある。

### 2.2 3つの原則

**番号の順に優先度が高い。**

1. **英語の語は、英語らしく聞こえる表記を優先する。**
   語末の/t//d/を`トゥ`・`ドゥ`とするのが代表例（`it`→`イットゥ`、`robot`→`ロボットゥ`）。日本語として多少ぎこちなくても、英語の発音に近い聞こえを選ぶ。

2. **ただし、日本語として不自然になる手前で止める。** 次の場合は日本語側の形を使う。
   * **英語以外に由来する語**（イタリア語の音楽用語`allegretto`→`アレグレット`、スペイン語`avocado`→`アボカド`、`Bologna`→`ボローニャ`）
   * **英語以外に由来する人名・地名**（`Suharto`→`スハルト`、`Puerto`→`プエルト`）
   * **日本語として定着した形がある語**（`cello`→`チェロ`、`euro`→`ユーロ`、`motto`→`モットー`、`zero`→`ゼロ`）
   * **日本語の音韻から離れすぎる細工**（/si/を`スィ`と書く類。辞書全体で1.3%しか使われておらず、事実上不採用）

3. **聞き分けやすさが損なわれる場合は、英語らしさより優先する。**
   [issue #4](https://github.com/actlaboratory/englishToKanaConverter/issues/4)で`why`を`ワイ`にせず`ホワイ`のままとしたのは、英語の実際の発音では`wh`が消えていても、`Y`との区別がつかなくなるためである。

### 2.3 原則1は「聞こえ」の規定である

原則1は読み上げたときの音についての規定であり、表記の見た目ではない。`V`を`ヴ`ではなくバ行で書くのは、日本語TTSの多くが`ヴ`を実質`ブ`と発音するため、`ヴ`を使っても聞こえが英語に近づかないからである。聞こえが変わらない表記上の細工は、原則2に言う「日本語の音韻から離れた細工」にあたる。

### 2.4 原則2の「定着した形」の範囲

**日本語の一般語彙になりきった語に限る。** 英語の固有名詞やブランド名は原則1の対象である。

| 原則2（定着した形を使う） | 原則1（英語らしく） |
| --- | --- |
| `auto`→`オート`、`photo`→`フォト` | `Microsoft`→`マイクロソフトゥ` |
| `cello`→`チェロ`、`euro`→`ユーロ` | `Internet`→`インターネットゥ` |
| `tuxedo`→`タキシード` | `Hollywood`→`ハリウッドゥ` |
| `poly`→`ポリ`、`epoxy`→`エポキシ` | `Reddit`→`レディットゥ` |

英語圏の人名・地名も原則1に従う（`Richard`→`リチャードゥ`、`England`→`イングランドゥ`、`Stanford`→`スタンフォードゥ`）。原則2の人名の例外は、英語以外に由来するものに限られる。

## 3. カテゴリ別の規則

### 3.1 語末の子音 /t/ /d/

`トゥ`・`ドゥ`と書く（原則1）。`get`→`ゲットゥ`、`robot`→`ロボットゥ`、`android`→`アンドゥロイドゥ`。

英語以外に由来する語は対象外（`allegretto`→`アレグレット`、`avocado`→`アボカド`）。なお`alto`→`アルト`のように**見出し語が母音で終わる**場合、その`ト`は語末子音/t/ではなく音節/to/なので、そもそもこの規則の対象ではない。

### 3.2 否定接頭辞＋母音で始まる語

`un-`・`in-`のように子音で終わる否定接頭辞に母音始まりの基語が続く場合、**接頭辞の`ン`を保持し、余分な音を挿入せず、基語の読みへ直接連結する**（原則3）。

* `un`(`アン`)＋`able`(`エイブル`)＝`unable`→`アンエイブル`
* `in`(`イン`)＋`organic`(`オーガニック`)＝`inorganic`→`インオーガニック`

基語の頭母音を消したり（`アネイブル`）、聞き取りやすさのために子音を追加したり（`アンナベイラブル`）しない。基語は独立した単語として登録されている読みをそのまま使う。

**適用対象は、現代英語話者にも「否定＋既存の語」という構造が透けて見える生産的な複合語に限る。** 語源的には接頭辞＋基語でも、現代英語では分割されない語には適用しない。

* `disease`→`ディジーズ`（`ディスイーズ`ではない）、`disaster`→`ディザスター`
* `union`・`unique`・`unionize`（`uni-`＝「一つの」に由来し、否定の`un-`ではない）

### 3.3 `V`の読み

**バ行（`バ・ビ・ブ・ベ・ボ`）で書く。`ヴ`は使わない**（原則2、2.3節参照）。

`violin`→`バイオリン`、`Venus`→`ビーナス`、`interview`→`インタビュー`。

`ヴ`は直後の小書き母音と組んで1モーラを構成するため、置き換える際は`ヴァ`→`バ`、`ヴィ`→`ビ`、`ヴェ`→`ベ`、`ヴォ`→`ボ`、`ヴュ`→`ビュ`、単独の`ヴ`→`ブ`と対応させる。

### 3.4 `th`の読み

無声/θ/と有声/ð/を区別する。語ごとに実際の発音に従うが、**同じ語族の中では表記を揃える**。

* 無声/θ/＋/i/は`スィ`と書く（`think`→`スィンク`、`thick`→`スィック`）。同じ語族の一部だけ`シ`にしない。
* ただし`theater`→`シアター`のように、語族全体が`シ`で定着している場合はそのまま（原則2）。
* 有声/無声の判断は、直接対照できる同型の語がある場合に限って修正する（`strength`→`ストゥレングス`と`length`→`レングス`など）。確証が持てない場合は変更しない。

### 3.5 語末`-Y`の長音

**長音記号`ー`で書く**（`ability`→`アビリティー`、`academically`→`アカデミカリー`）。`イ`や小書きの`ィ`は使わない。

内閣告示「外来語の表記」の長音の書き方に合致し、`パーティー`・`アカデミー`といった一般的な外来語表記とも整合する。

**重要な注意**: 語末の`イ`がすべて長音とは限らない。直前の仮名がイ段でない場合、それは長音ではなく**二重母音**であり、`イ`が必須である。

| 直前の仮名 | 意味 | 例 |
| --- | --- | --- |
| イ段 | 長音 /iː/ | `acclivity`→`アクリビティー` |
| ア段 | 二重母音 /ai/ | `ally`→`アライ`、`apply`→`アプライ` |
| エ段 | 二重母音 /ei/ | `allay`→`アレイ`、`Ashley`→`アシュレイ` |
| オ段 | 二重母音 /oi/ | `annoy`→`アノイ`、`alloy`→`アロイ` |

`poly`→`ポリ`、`epoxy`→`エポキシ`のように日本語として短い形が定着している語は対象外（原則2）。

### 3.6 /oʊ/（`goat`の母音）の表記

**位置によって扱いが異なる。**

**語中の/oʊ/は`オウ`と書く**（原則1）。`boat`→`ボウトゥ`、`code`→`コウドゥ`、`total`→`トウタル`、`local`→`ロウカル`、`motor`→`モウター`、`motion`→`モウション`。

**語末の/oʊ/は機械的に統一しない。** 語ごとに、日本語として定着した形があればそれを優先し（原則2）、なければ`オウ`を用いる（原則1）。

| 定着形がある | 定着形がない |
| --- | --- |
| `zero`→`ゼロ`、`memo`→`メモ` | `ago`→`アゴウ` |
| `cello`→`チェロ`、`euro`→`ユーロ` | `also`→`オールソウ` |
| `mango`→`マンゴー`、`echo`→`エコー` | `albino`→`アルバイノウ` |

**/oʊ/と/ɔː/を混同しないこと。** カナの上ではどちらも「オ段＋`ー`」になり得るが、/ɔː/は`オー`のままである（`north`→`ノース`、`tall`→`トール`、`walk`→`ウォーク`、`audit`→`オーディットゥ`）。また`bamboo`→`バンブー`、`zoo`→`ズー`、`into`→`イントゥー`のような/uː/も別物である。

### 3.7 日本語のローマ字は登録しない

日本語をローマ字表記した見出し語（`Abashiri`→`アバシリ`、`Chibaken`→`チバケン`、`desu`→`デス`）は登録しない。`roman.json`によるローマ字変換で処理される。

ただし次は登録してよい。

* **英語の語彙・固有名詞として通用するもの**（`Tokyo`→`トウキョウ`、`tofu`→`トウフ`、`ninja`→`ニンジャ`、`Sony`→`ソニー`、`Shinto`→`シントー`）
* **ローマ字変換では正しく読めないもの**（`onyaku`→`オンヤク`。登録を外すと`nya`が拗音と解釈され`オニャク`になる）

### 3.8 日本語として成立しない読みは書かない

次のような仮名の並びは、日本語のカタカナ表記として成立しない。登録前に確認すること。

* 長音記号の重複（`ーー`）、語頭の`ー`、撥音`ン`の直後の`ー`
* 語頭の小書き仮名（`ェンクリプション`のような形）
* 語末の促音`ッ`、`ッ`や`ン`の重複

なお**拗音・促音を表す小書き仮名の連続は正常**である（`ティッドゥ`＝`ィ`＋`ッ`、`キャッツ`＝`ャ`＋`ッ`）。これを異常として扱わないこと。

## 4. 新規登録の手順

1. **その語は英語か。** 英語以外に由来する語（イタリア語・スペイン語の音楽用語や料理名、非英語圏の人名・地名）であれば、日本語での慣用形をそのまま使う。以降の手順は適用しない。

2. **日本語として定着した形があるか。** `チェロ`・`ユーロ`・`タキシード`のように日本語の一般語彙になっている場合はそれを使う。ただし英語の固有名詞・ブランド名は定着形があっても原則1に従う（`マイクロソフトゥ`）。

3. **3章の該当する規則を適用する。** 語末の/t//d/、`V`、`th`、語末`-Y`、/oʊ/など。

4. **同じ語族の既存エントリーを確認する。** 活用形や派生語が既に登録されている場合、表記を揃える。`grep`等で語幹を検索し、`conserve`／`conserved`／`conserving`のような組で食い違いが生じないようにする。

5. **どの辞書に登録するかを決める。** 5章参照。

6. **3.8節の観点で読みを確認する。**

7. **`python tools/optimizeDic.py`を実行する。** ソートと形式の正規化が行われ、使用できない文字があれば警告が出る。

判断に迷い、複数の読みがあり得る場合は、選んだ理由をコミットメッセージに残しておくと後の判断材料になる。

## 5. `phrases.json`と`words.json`の使い分け

この2つは**複合語の部品として使われるかどうか**が決定的に違う。

| ファイル | 用途 |
| --- | --- |
| `phrases.json` | 通常の単語辞書。複合語を分解する際の**部品としても使われる** |
| `words.json` | 英字列**全体が完全一致**した場合にのみ使う。複合語の部品には**一切使われない** |

したがって、**短い語が他の長い語を誤って分解してしまう場合は`words.json`に置く**。

例えば`do`→`ドゥー`が`phrases.json`にあると、`bando`が`ban`＋`do`と分解されて`バンドゥー`になってしまう。`words.json`へ移せばこの問題は起きない。同じ理由で`to`・`no`・`an`・`as`・`at`・`is`・`if`・`me`・`us`などは`words.json`に置かれている。

ただし移す際は注意が必要である。その語を**部品として正しく使っていた語**が読めなくなるため、それらを`phrases.json`へ個別登録する必要がある。`do`を移した際は`undo`・`outdo`・`overdo`・`misdo`・`doable`・`hairdo`を追加した。

## 6. 許容している既知の制約

`suffix.json`（`-S`・`-ed`・`-ing`・`-ly`等）は、未登録語を救済するためのフォールバックであり、**単純な文字列連結しか行わない**。そのため、実際の英語の音便変化（`abate`＋`D`は`アベイトゥドゥ`ではなく`アベイティドゥ`）とは食い違う。

この乖離は**許容する**。影響は「基語は登録されているが屈折形は未登録」という限定的なケースにとどまり、最終手段の1文字ずつのスペルアウトよりはましな近似が得られるためである。屈折形の読みを正確にしたい場合は、その語を`phrases.json`に個別登録すればよい。
